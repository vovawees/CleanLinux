PITFALLS met so far
- NEVER edit bootstrap/bootstrap.sh while a bootstrap run is in progress: bash reads the main script lazily by
  offset, the running loop would resume mid-text. Sourced lib.sh is read whole at source time (safe to edit).
  If needed: keep the edit elsewhere, `cat original > bootstrap.sh` (same inode), restore after the run.
- mkfs.btrfs --help | grep -q under pipefail: SIGPIPE -> false failure; capture output in a variable first.
- xorriso -smbios / qemu: commas inside -smbios value must be doubled.
- systemd-boot reads SMBIOS type 11 io.systemd.boot.kernel-cmdline-extra= (Type #1 entries) -- used by tests.
- Amazon Linux meson is too old (0.63 needs distutils): bootstrap uses the meson recipe's tarball (host_meson).
- libblkid sees the iso9660 label on the whole stick AND on partition 1 -> live_medium tries each.
- Rufus ISO mode copies files to FAT (label truncated to 11 chars) -> live medium not found: document DD mode.
- burn.conf FIRMWARE in the live root is inherited by installs; device profiles must not inherit it (conf_unset).
- cleanlinux-install tarball must not be committed: .gitignore /cleanlinux-install-*.tar.gz (make dist output).
- sandbox: no KVM -> QEMU TCG (ISO boot to installer ~40 s, full tests/iso.py 2-4 min); 2 CPUs, 4 GB RAM, 32 GB disk.
- cryptsetup (initramfs) writes its prompt, THEN tcsetattr(TCSAFLUSH) turns echo off and drops pending input: a
  passphrase sent the moment the prompt shows is echoed and thrown away, the boot waits forever. Tests wait 3 s.
- tzdata: zic is a host tool; build it with `env -u CC ... make CC=gcc cc=gcc` (cross CC leaks otherwise).
- linux-firmware: newer releases keep licenses in LICENSES/ (a directory): install loops over LICEN[CS]E* LICENSES/*.
- mount(2) probing every fs of /proc/filesystems prints "VFS: Can't find ext4 filesystem" / "Can't find a SQUASHFS
  superblock" unless MS_SILENT (cleanlinux-boot >= 0.4.1 passes it, as the kernel does for the root).
- pam_motd in system-login AND login(1) printing /etc/motd = motd twice (pambase >= 2026.1-3 drops pam_motd).
- tests/iso.py screen matching: the TUI box border is part of the line ("| > /dev/vda"); the progress screen can be
  skipped entirely on a fast run: wait for any_of("Разметка диска", "Копирование пакетов", "CleanLinux установлен",
  "Установка не удалась").
- `pkill -f PATTERN` inside a bash -c whose own command line contains PATTERN kills that shell (exit 143).
- this QEMU (Amazon Linux) has no user (slirp) networking: tests use nic_args() (hubport NIC, no network).
- glibc >= 2.35 has a C.UTF-8 locale but NOT built in: it must be compiled (glibc 2.44-2 recipe: make -C
  $SRC/localedata objdir=$BUILD install_root=$DESTDIR install-files-C.UTF-8/UTF-8, runs the built localedef via
  the built ld.so -> only natively or cross for the host arch). Before it: LANG=C.UTF-8 of /etc/profile = C locale.
- cmake's own C++ feature checks (cm_cxx_unique_ptr...) treat ANY "warning" in the compiler output as failure:
  a bash "warning: setlocale: LC_ALL: cannot change locale" (missing C.UTF-8) broke the native cmake bootstrap.
- burn orders builds by depends+makedepends only: build_type=cmake needs makedepends=(cmake) (ninja did not).
- "shell-init: error retrieving current directory" in perl/cmake build logs: dirs removed under running
  shells (CMakeTmp, UU) -- harmless.
